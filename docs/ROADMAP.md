# 后续功能清单与排期（Roadmap）

> 基线：`dev` 分支（Markdown 编辑器交互已对齐 Typora，并已支持 Markdown 导入 / 导出）。
> 本文档回答两件事：**接下来该加什么功能**、**什么时候做**。
> 排期按 **1 名全栈开发**估算（每个 2 周迭代约 10 个有效人日）；如果前后端能并行，
> 标注的工期可以压缩 30%～50%，但依赖关系（数据库/接口 → 页面）不变。

## 4. 排期假设与风险

1. **人力假设**：1 名全栈开发，每迭代 10 个有效人日；需求变更超过 2 人日需要挪到下个迭代。
2. **MinIO 镜像**：社区版已停止发布镜像（README 已提示），上线前需固定自建镜像仓或切换 RustFS 等 S3 兼容实现，**不阻塞功能开发，阻塞部署**。
3. **邮件能力**：P1-7 依赖 SMTP 账号（企业邮箱/发信服务），没有账号时先做站内通知。
4. **数据迁移**：P0-7 版本历史、P1-1 通知、P1-2 点赞收藏需要新增表，统一走 `sql/init.sql` 增量脚本 + Flyway（建议在 Sprint 2 一并引入）。
5. **测试环境**：P2-1/P2-2 依赖 Docker（Testcontainers）与 Playwright 浏览器，CI 机器需预留资源。

## 5. 本次交付：Markdown 导入 / 导出

编辑器「文件」菜单新增 5 项，均在前端完成、不新增后端接口：

| 菜单项 | 行为 |
| ---- | ---- |
| 新建（`Ctrl+N`） | 正文为空直接清空；非空先弹确认框，清空后仍可 `Ctrl+Z` 撤销 |
| 导入 Markdown…（`Ctrl+O`） | 选择或拖入 `.md/.markdown/.mdown/.mkd/.mdx/.txt`；正文为空直接导入，非空时弹框选择「替换正文 / 插入到光标处」；自动去 BOM、CRLF → LF；标题为空时用文档首个标题或文件名回填 |
| 导出 Markdown… | 下载 `.md`，文件名取文章标题 → 正文首个标题 → 日期 |
| 导出 HTML… | 生成独立 HTML：纸张排版 + GitHub 代码高亮，样式与阅读页一致，可直接分享/存档 |
| 导出 PDF… | 浏览器端按块分页，批量用 SVG `foreignObject` 原生渲染后由 jsPDF 拼成 A4 PDF **直接下载**（不弹打印框）；页数越多自动降分辨率；中文为图片、不可选中复制；跨域图片显示为占位符 |

**长文档性能（本次一并优化）**：Markdown 文本缓存 + 大纲/字数防抖，导入、切换源码模式、生成 PDF
时显示遮罩；切换源码模式跳过 Vditor 对整篇文档的 undo diff。138KB / 7100 行文档实测：
导入 5.3s → 1.9s，切到源码模式 3.0s → 0.2s（切回即时渲染约 1.1s），800 个标题的大纲正常；
PDF 改为批量 SVG 渲染后，60 页约 3.3s、300 页约 10s（约 33MB），而逐页 html2canvas 需要数分钟。

后续可扩展（未排期）：导入整个文件夹/zip、PDF 文字可选（服务端渲染/嵌入中文字体）、导出时附带图片资源打包、
MinIO 配置 CORS 让 PDF 直接内联图片。

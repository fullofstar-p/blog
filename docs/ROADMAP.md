## 4. 排期假设与风险

1. **人力假设**：1 名全栈开发，每迭代 10 个有效人日；需求变更超过 2 人日需要挪到下个迭代。
2. **MinIO 镜像**：社区版已停止发布镜像（README 已提示），上线前需固定自建镜像仓或切换 RustFS 等 S3 兼容实现，**不阻塞功能开发，阻塞部署**。
3. **邮件能力**：P1-7 依赖 SMTP 账号（企业邮箱/发信服务），没有账号时先做站内通知。
4. **数据迁移**：P0-7 版本历史、P1-1 通知、P1-2 点赞收藏需要新增表，统一走 `sql/init.sql` 增量脚本 + Flyway（建议在 Sprint 2 一并引入）。
5. **测试环境**：P2-1/P2-2 依赖 Docker（Testcontainers）与 Playwright 浏览器，CI 机器需预留资源。

## 5. 本次交付：Markdown 导入 / 导出

编辑器「文件」菜单新增 5 项，均在前端完成、不新增后端接口：

| 菜单项 | 行为 |
| ---- | ---- |
| 新建（`Ctrl+N`） | 正文为空直接清空；非空先弹确认框，清空后仍可 `Ctrl+Z` 撤销 |
| 导入 Markdown…（`Ctrl+O`） | 选择或拖入 `.md/.markdown/.mdown/.mkd/.mdx/.txt`；正文为空直接导入，非空时弹框选择「替换正文 / 插入到光标处」；自动去 BOM、CRLF → LF；标题为空时用文档首个标题或文件名回填 |
| 导出 Markdown… | 下载 `.md`，文件名取文章标题 → 正文首个标题 → 日期 |
| 导出 HTML… | 生成独立 HTML：纸张排版 + GitHub 代码高亮，样式与阅读页一致，可直接分享/存档 |
| 导出 PDF… | 浏览器端按块分页，批量用 SVG `foreignObject` 原生渲染后由 jsPDF 拼成 A4 PDF **直接下载**（不弹打印框）；页数越多自动降分辨率；中文为图片、不可选中复制；跨域图片显示为占位符 |

**长文档性能（本次一并优化）**：Markdown 文本缓存 + 大纲/字数防抖，导入、切换源码模式、生成 PDF
时显示遮罩；切换源码模式跳过 Vditor 对整篇文档的 undo diff。138KB / 7100 行文档实测：
导入 5.3s → 1.9s，切到源码模式 3.0s → 0.2s；源码没改时切回即时渲染约 6ms（大文档只保留少量
切换开销，复用 IR DOM），改过才重建。大纲侧栏改为覆盖式 + 首次打开才挂载 + 关闭期间只记 dirty，
800 个标题首次打开约 55ms、来回切换 5～30ms，且不再让大文档重排。
PDF 改为批量 SVG 渲染后，60 页约 3.3s、300 页约 10s（约 33MB），而逐页 html2canvas 需要数分钟。

后续可扩展（未排期）：导入整个文件夹/zip、PDF 文字可选（服务端渲染/嵌入中文字体）、导出时附带图片资源打包、
MinIO 配置 CORS 让 PDF 直接内联图片。

## 6. 本次交付：自动保存草稿（P0-2）与回收站（P0-8）

### 6.1 自动保存草稿

| 层 | 行为 |
| ---- | ---- |
| 本地草稿 | 编辑器内容变化后 700ms 防抖写入 `localStorage`（按页面存：新文章 `blog:article-draft:new`，编辑页 `blog:article-draft:{id}`），刷新/重进时检测到较新草稿会弹「发现未保存的草稿」，可恢复或丢弃；恢复后继续自动保存 |
| 服务端草稿 | 草稿（`status=0`）每 15 秒把标题/正文/摘要/封面/分类/标签写回服务端；新文章第一次自动保存会创建草稿并记住 ID，之后都走更新，不重复建稿；已发布文章**不会**被自动保存改线上内容，只保留本地草稿 |
| 离开提醒 | 有未保存修改时关闭标签页触发浏览器 `beforeunload`，站内路由跳转弹确认框；离开前会先落一次本地草稿，回来后仍可恢复 |
| 状态提示 | 编辑器右上角实时显示「本地草稿已保存 / 正在自动保存 / 已自动保存 HH:mm:ss / 自动保存失败」，有未保存修改时提示「有未保存修改」 |

实现集中在 `frontend/src/views/admin/AdminArticleEdit.vue` 与 `frontend/src/utils/articleDraft.js`；
服务端沿用现有文章新增/更新接口（`POST /api/articles`、`PUT /api/articles/{id}`），未新增接口。

### 6.2 回收站

| 能力 | 行为 |
| ---- | ---- |
| 软删除 | 删除文章改为 `deleted=1` 并记录 `deleted_time`，文章标签关联保留（恢复后标签不丢） |
| 回收站列表 | 新增 `GET /api/admin/articles/recycle`（按标题/摘要搜索、分页、按删除时间倒序） |
| 恢复 | `PUT /api/admin/articles/{id}/restore`，恢复后回到文章列表；已发布文章恢复后重新对外可见 |
| 彻底删除 | `DELETE /api/admin/articles/{id}/purge`，物理删除文章并清理 `article_tag` 与评论，不可恢复 |
| 前台可见性 | 已删除文章不再出现在列表 / 搜索 / 归档 / 详情 / 上一篇下一篇，详情缓存同步失效 |

数据库变更：`article` 表新增 `deleted_time DATETIME NULL` 与 `idx_article_deleted_time`。
全新初始化见 `sql/init.sql`；已有库执行一次 `sql/upgrade-2026-10-p0-8-recycle.sql`。
管理后台新增「回收站」入口（`/admin/recycle`），删除确认文案同步改为「进入回收站，可以恢复」。

## 7. 本次交付：暗色模式（P0-10）

### 7.1 交互与持久化

| 能力 | 行为 |
| ---- | ---- |
| 三种主题 | 顶栏主题按钮打开菜单：**跟随系统 / 浅色 / 深色**；当前项打勾，可随时切换 |

| 手动固定 | 选择浅色/深色后写入 `localStorage`（`blog.theme`），刷新、重新打开浏览器都保持；多标签页通过 `storage` 事件同步 |
| 无闪白 | `index.html` 在首屏渲染前读取主题并给 `<html>` 加 `dark` + `color-scheme`，暗色用户不会先看到一帧白纸；`meta theme-color` 同步更新 |
| 主题按钮 | 顶栏固定入口（44px 触控区），图标随当前主题显示 ◐ / ☀ / ☾；菜单支持点击外部与 `Esc` 关闭 |

### 7.2 配色体系

- 颜色不再写死在组件里：`tailwind.config.js` 的 `paper / pencil / ink / sketchred / sketchgreen / sketchyellow / sketchblue / overlay` 全部绑定 `src/styles/main.css` 的 CSS 变量；`html.dark` 只覆盖一套变量，整站换色。
- 亮色保持原有米色纸张 + 铅笔灰；暗色改用**暖黑纸张**（`#1b1a17` / `#1c1b18` / `#23211d`）+ **粉笔白**（`#e7e1d5` / `#d9d3c6`），强调色换成低饱和亮色（红 `#e07a6e`、绿 `#6fc79a`、蓝 `#7cb3d6`、黄 `#d6ad5c`），手绘阴影改为纯黑投影。
- 散落在 26 个 Vue/JS 文件里的 `text-[#b23b2e]` 一类固定色，统一收敛为 `text-sketchred` 等语义 token；组件里不再需要逐个写 `dark:` 变体。

### 7.3 Markdown 编辑器与阅读页

- 阅读页：`--md-*` 排版变量在暗色下整体覆盖（正文/标题/边框/表格斑马纹/引用/行内代码/代码块底色），代码高亮换成 GitHub Dark 色系；纸张页面、目录、进度条、移动端目录抽屉、复制按钮都有暗色样式。
- 编辑器：Typora 外壳（菜单栏、下拉菜单、大纲侧栏、状态栏、源码模式、链接/导入对话框、长任务遮罩、代码块语言列表、表格工具条、全屏）逐项覆盖；Vditor 的代码块预览层、编辑层光标/选区、`--ir-*` 标记色同步调整。
- 导出保持浅色：导出的 Markdown / 独立 HTML / PDF 仍使用纸张浅色排版，不跟随界面暗色，避免导出文件在白天/打印时不可读。

实现文件：`src/store/theme.js`、`src/components/ThemeToggle.vue`、`src/styles/main.css`、`src/styles/markdown.css`、`src/styles/markdown-reading.css`、`index.html`。

验证：主题跟随/手动切换/刷新持久化、系统深浅切换实时跟随、移动端无横向溢出、各页面暗色无可见纯白底块、浅色回归；E2E（无头 Edge）24 项全部通过。

### 8.1 统计采集

- 访问已发布文章详情时：Redis `INCR` 当日 PV、`PFADD` 当日 UV HyperLogLog（登录用户取 `u:{id}`，匿名取 `IP + User-Agent` 的 SHA-256，不保存原始 IP）、`HINCRBY` 文章当日阅读量，并记录待落库日期。
- `StatsSyncTask` 每 60 秒把增量写入 MySQL：`site_daily_stat`（日期、PV、UV）与 `article_daily_stat`（文章、日期、PV）；PV 用 `GETDEL`/`RENAME` 避免落库期间新增的访问丢失，UV 用当日 HLL 快照取最大值。
- 看板读取历史库，再叠加当天尚未落库的 Redis 增量，做到“今日实时、历史可查”。
- 草稿预览与未登录不可见文章不计数；彻底删除文章时同步清理其每日统计。
- **历史数据说明**：PV/UV 与文章每日阅读从本版本上线后开始采集；上线前的阅读量只有文章表的总阅读量
  `view_count`，因此趋势图/区间数据不会回填历史（总阅读卡片仍展示累计值），发布热力图按文章
  `create_time` 可回看过去一年。
